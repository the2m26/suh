# CUTOVER — suh.html → admin-react шилжилтийн бэлэн байдал

*Бэлдсэн огноо: 2026-08-06 (v11 chat, React шилжилтийн эцсийн шат)*

## 1. Ерөнхий төлөв

Strangler Fig аргачлалаар 0→4-р түвшин (0=суурь, 1=мэдээ/санал асуулга/хаалт, 2=CRUD бүртгэл, 3=санхүүгийн цөм, 4=үлдсэн+cutover) бүгд React рүү шилжсэн. **18 маршрут**, **62 vitest тест** (бүгд ногоон), `npm run build` цэвэр.

`suh.html` энэ баримт бичиг батлагдаж, доорх алхмуудыг гүйцэтгэх хүртэл **устгагдахгүй, идэвхтэй хэвээр үлдэнэ** — Strangler Fig-ийн үндсэн зарчим.

## 3. ЗААВАЛ шийдвэрлэх — cutover-ийн ӨМНӨ

1. **Ажилтны татварын override/нэмэгдэл тохируулах UI** (`Employees.jsx`-д алга) — payroll тооцоолол зөв ажиллаж байгаа ч тохиргоог зөвхөн suh.html-ээс өөрчилж болно. Cutover хийхээс өмнө эсвэл шууд дараа нь энэ UI-г нэмэх шаардлагатай, эс тэгвэл ажилтны татварын тохиргоо өөрчлөх бүрд suh.html рүү буцах хэрэгтэй болно.
2. **НБ тайлангийн 8 үлдсэн хэсэг** (Балансын тайлан/Орлогын тайлан А маягт, Мөнгөн гүйлгээ, Хандлага, Насжилт, Гүйлгээний дэлгэрэнгүй, Хуулга, Цалингийн нэгтгэл, Элэгдлийн хураангуй) — жилийн эцсийн албан ёсны тайлан гаргахад шаардлагатай бол заавал.
3. **CC center Realtime** — realtime байхгүй тул ажилтан гараар thread сонгож л шинэчлэлт харна; олон ажилтан зэрэг ашиглах үед анхаарал хандуулах.

## 4. Хойшлуулж болох (cutover-ийг блоклохгүй)

- Мэдээний лайтбокс, Санал хураалтын xlsx экспорт
- Barcode SVG дүрслэл (текст хэвээр байж болно)
- НД-7/НД-8, AI Integration Plan, Cosmo, Market valuation — эдгээр нь эх suh.html талд ч бэлэн бус байсан тул React рүү шилжүүлэх зүйл харьцангуй бага

## 5. Cutover-ийн алхамчилсан төлөвлөгөө

1. **Параллель тест үе** (2-4 долоо хоног санал болгож байна): admin-react-ийг бодит хэрэглэгчидтэй (жинхэнэ Supabase дата дээр) turshиж, suh.html-тэй зэрэгцүүлж үр дүнг харьцуулах — ялангуяа санхүүгийн тооцоолол (calcFee/allocatePaymentToMonths/payroll)
2. **Ажилтны эрхийн шалгалт**: role_permissions хүснэгэл дэх бүх мөр admin-react-ийн AUTH_MODULES-тэй таарч байгааг баталгаажуулах
3. **§3-ын заавал зүйлсийг шийдэх**
4. **suh.html-ийн "⚛ React (турших)" холбоосыг үндсэн болгож солих** — эсвэл шууд admin-react/-ийг үндсэн нэвтрэх цэг болгож, suh.html-д "← Хуучин систем рүү (deprecated)" холбоос үлдээх
5. **suh.html-ийг idle болгох** (УСТГАХГҮЙ — Дүрэм: 100% шилжсэний ДАРАА л унтраана) — GitHub Pages дээр хэвээр байлгаж, зөвхөн nav-аас нуух
6. **DNS/nginx/GitHub Pages тохиргоонд** admin-react/ -ийг `/suh/` root болгож дахин чиглүүлэх эсвэл хэрэглэгчдэд шинэ URL-ыг мэдэгдэх

## 6. Техникийн тэмдэглэл

- `npm run build` → `dist/` GitHub Pages-ийн `/suh/admin-react/` дэд хавтаст байршина (vite.config.js `base` тохиргоо аль хэдийн зөв)
- `npm test` — vitest, бүх санхүүгийн/тооцооллын логик регресс тестээр хамгаалагдсан
- Архитектурын шийдвэр 2-ын дагуу: suh.html-д шинэ модуль/талбар нэмэгдэх бүрд admin-react-ийн харгалзах файлыг мөн зэрэг шинэчлэх шаардлагатай (README.md-д жагсаасан)
